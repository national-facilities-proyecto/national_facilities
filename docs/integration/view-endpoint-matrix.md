# Matriz de vistas y endpoints

Integración en `feature/sprint1-alex-frontend`, 2026-10-01–2026-10-02. Checklist de implementación y comprobación. Todas las rutas operativas usan HTTP real y PostgreSQL; E2E significa navegador con Django real/base aislada. Los dobles se usan únicamente en Vitest.

Base HTTP `/api/`. T=técnico; ST=supervisor de tienda; SC=supervisor de cuenta; A=administrador. La asignación activa de tienda define el alcance actual; se vuelve a comprobar en cada mutación. Propiedad y técnico vigente limitan ejecución. Detalle no autorizado se oculta con 404; rol o acción no autorizados se rechazan.

## Reglas transversales completadas

- [x] Fuente API única en dev/build/Compose; repositorios mock fuera del runtime, sin fallback.
- [x] DTO explícitos y validados; errores por campo y 400/401/403/404/409/red.
- [x] JWT renovable/revocable, cambio inicial obligatorio del servidor.
- [x] Mutaciones transaccionales; claves de idempotencia y revisión CAS.
- [x] Primera apertura y vencimiento originales; ejecución no limitada a cinco minutos.
- [x] Borradores/fotos recuperados desde servidor y estados de guardado confirmados.
- [x] Archivos privados multipart/Blob y eliminación controlada; cámara o galería.
- [x] GPS recalculado servidor contra ubicación/radio fijados; nulos históricos honestos.
- [x] Tiempo/GPS independientes, eventos con actor, solicitudes/decisiones fechadas.
- [x] Consultas con carga/vacío/error/retry; editor conserva contenido ante fallo y conflicto.
- [x] Refrescos conservan datos confirmados con estado visible; errores de permisos retiran datos. Administración pausa el refresco al editar y recarga al cerrar sin borrar campos.
- [x] Reportes con tiempos distintos, finalización pendiente vs aceptada y CSV.
- [x] Pruebas PostgreSQL concurrentes y recorridos de navegador con operaciones reales.

## Reglas confirmadas y pendientes

- [x] Rechazo con corrección/reenvío en la misma ejecución; incompleto editable sin renovar el plazo; historial de cada decisión.
- [x] Estados confirmados: Pendiente, En proceso, En revisión y Finalizado; no hay segunda etapa resuelto→cerrado.
- [x] Reserva sin iniciar de dos horas: liberación automática, historial, nuevo técnico y pantalla antigua rechazados; servicio periódico y E2E reales.
- [x] Cuotas mensuales independientes, identificadas por tienda/mes/número; sin separación mínima, mismo técnico permitido; generación concurrente y E2E de tres visitas.
- [x] El administrador asigna las tiendas del técnico; bolsa y ejecución se limitan a asignaciones activas y propietario vigente.
- [x] Contratos activos simultáneos del mismo cliente prohibidos; validación y exclusión PostgreSQL, fechas inclusivas y concurrencia.
- [x] Mínimo de dos atenciones de tickets por cada tienda/mes, separado del checklist; snapshot, filtro y datos reales del servidor.
- [x] Reasignación solo en Pendiente; inicio/reasignación concurrentes no crean dos ejecuciones.
- [x] Importación/regularización de trabajos previos al lanzamiento fuera del alcance por instrucción del usuario.
- [ ] SLA/calendario y feriados aplazados expresamente por el usuario.
- [ ] Verificación de almacenamiento privado GCS y despliegue real; sin credenciales/infraestructura.
- [x] Docker de desarrollo levantado por el usuario; migraciones 0012/0013 aplicadas y health 200 comprobado. E2E completos en base/backend nativos aislados.

Las opciones concretas están en [decisiones pendientes](decisions-pending.md); la [validación](../../frontend/docs/validation.md) registra evidencia y límites.
